## 1. 产品概述

### 1.1 产品定位

**产品分析一体化平台** 是一套面向 B2B 销售管理场景的数据分析平台，整合**产品宽度分析**与**潜力产品销售分析**两大核心能力，帮助管理层和销售人员全面掌握产品在客户/用户侧的覆盖情况，识别薄弱环节，制定精准的交叉销售策略。

### 1.2 目标用户

| 用户类型 | 使用场景 |
|----------|----------|
| 总经理 (GM) | 全局视角查看所有部门/团队的销售数据和产品覆盖表现 |
| 运营人员 | 数据导入、报表导出、监控整体业务指标 |
| 部门总监 | 查看本部门的产品宽度和潜力产品表现，管理下属团队 |
| 团队主管 | 查看本组数据，管理成员的产品销售覆盖 |
| 接口人 | 负责数据对接，查看和核对业务数据 |
| 一线销售 | 查看本人的产品覆盖情况和销售业绩 |

### 1.3 核心价值

1. **一目了然的数据总览** — 通过 KPI 卡片和可视化图表，快速掌握全平台产品宽度和潜力产品的经营现状
2. **全维度分析能力** — 支持从部门 → 小组 → 个人 → 客户 → 用户的任意维度下钻分析
3. **低宽度预警** — 自动识别产品覆盖不足的客户和用户，给出提升建议
4. **潜力产品洞察** — 11 个核心潜力产品的销售趋势、覆盖率排名、四象限诊断
5. **数据驱动决策** — 交叉销售推荐、产品套包组合、量价四象限等高级分析能力

## 2. 用户角色与权限

### 2.1 角色定义

| 角色 | 编码 | 数据范围 | 权限说明 |
|------|------|----------|----------|
| 管理员 | `admin` | 全租户 | 全部功能 + 用户管理 + 备份恢复 + 审计日志查看 |
| 总经理 | `gm` | 全租户 | 全局查看 + 导出备份 |
| 运营 | `operation` | 全租户 | 全局查看 + 数据导入导出 + 审计日志 |
| 总监 | `director` | 本部门 | 本部门数据查看 + 导出 |
| 主管 | `manager` | 本小组 | 本组数据查看 |
| 接口人 | `interface` | 本部门 | 数据对接与查看 |
| 一线销售 | `sales` | 仅本人 | 本人数据查看 |

### 2.2 数据隔离规则

```
全租户 (admin / gm / operation)
  └── 部门 (director)
        └── 小组 (manager)
              └── 个人 (sales)
```

- 高层级角色可查看下级数据
- 同层级之间数据隔离
- 租户间数据完全隔离

### 2.3 组织架构

平台基于 **租户 → 部门 → 小组 → 个人** 的四级组织架构：

- **租户:** 深圳业务中心
- **部门 (6个):** 客户销售一部、客户销售二部、大客户销售部、场景数字化销售部、行业一部、行业二部
- **小组 (18个):** 包括客户销售一组~九组、工业企业一组/二组、智慧商贸组、智慧建筑组、交通行业组、公安交警行业组、司法行业组、政府行业组、文教卫组

### 3.2 产品宽度分析

**路由:** `/api/width`

**页面入口:** 顶栏导航「📐 产品宽度分析」

**业务定义:**  
- **产品宽度** = 一个客户/用户购买的产品品类数量（共 27 个常规产品品类）
- **规上客户** = 产品宽度 ≥ 阈值（默认 3）的客户
- **覆盖率** = 覆盖某产品的客户数 / 总客户数 × 100%

| 内容 | 说明 |

| 产品宽度对比 | 部门/组维度的产品宽度对比图 |
| 产品覆盖率图表 | 27品类的客户/用户覆盖率柱状图 |
| 产品覆盖热力图 | 27品类 × 覆盖率 的彩色热力图矩阵 |
| 人均产品宽度趋势 | 近12月趋势折线图 |

##### Tab 2: 📦 产品维度

| 内容 | 说明 |
|------|------|
| 产品覆盖率排名 (客户) | 27品类按规上客户覆盖率排名 |
| 产品覆盖率排名 (用户) | 27品类按规上用户覆盖率排名 |
| 产品交叉销售关联矩阵 | 核心品类之间的 Lift 提升度矩阵（颜色越深 = 关联越强） |
| 产品套包组合 | 高频协同购买的2-3产品组合 |

##### Tab 3: 👥 团队维度

| 内容 | 说明 |
|------|------|
| 数据明细表 | 部门/组/个人三维度可切换，含排序、搜索、宽度过滤、分页 |
| 差距分析 | 团队 vs 部门均值的差距对比，识别先进/落后团队 |
| 导出功能 | 支持当前视图数据一键导出 Excel |

##### Tab 4: 🔑 客户维度

| 内容 | 说明 |
|------|------|
| 低宽度客户分析 | 宽度低于阈值的客户列表，展示已有产品 + 建议补充品类 |
| 客户分层 (优质/待提升) | Top10 优质客户 vs 后10 待提升客户对比 |
| 客户产品覆盖明细 | 完整客户-产品覆盖矩阵表，支持规上筛选、搜索、排序、分页 |

##### Tab 5: 🏢 用户维度

| 内容 | 说明 |

| 用户产品覆盖明细 | 完整用户-产品覆盖矩阵表，支持规上筛选、搜索、排序、分页 |

### 3.6 数据导出

**路由:** `/api/export`

#### 导出类型

| 导出内容 | API | 格式 | 权限 |
|----------|-----|------|------|
| 产品宽度数据 | `GET /api/export/width` | Excel (.xlsx) | 登录用户 |
| 潜力产品数据 | `GET /api/export/potential` | Excel (.xlsx) | 登录用户 |
| 审计日志 | `GET /api/export/audit` | Excel (.xlsx) | admin, gm, operation |

#### 导出特性

- 支持 openpyxl 生成标准 .xlsx 文件
- 兜底方案：纯 CSV 导出（无需 openpyxl 依赖）
- 文件编码：UTF-8-BOM（确保中文在 Excel 中正常显示）
- 单次导出上限：10,000 行（产品宽度/潜力产品）/ 5,000 行（审计日志）

|------|-----|------|

| 备份列表 | `GET /api/backup/list` | 列出所有备份文件及大小 |
| 恢复备份 | `POST /api/backup/restore/{filename}` | 从指定备份恢复数据 |
| 下载备份 | `GET /api/backup/download/{filename}` | 下载备份文件 |
| 删除备份 | `DELETE /api/backup/{filename}` | 删除指定备份文件 |

#### 备份范围

备份覆盖全部数据表：
- tenants（租户）
- departments（部门）
- groups（小组）
- users（用户）
- products（产品字典）
- sales_width（产品宽度销售数据）
- sales_potential（潜力产品销售数据）
- import_records（导入记录）
- audit_logs（审计日志）

#### 恢复机制

- 先清空目标租户的现有数据
- 按依赖顺序（部门 → 小组 → 用户 → 产品 → 销售数据 → 日志）重新插入
- 保留原始 ID

## 5. 业务概念定义

### 5.1 产品宽度 (Product Width)

一个客户或最终用户购买的产品品类数量。平台共有 **27 个常规产品品类**，客户购买的产品品类数越多，产品宽度越大。

### 5.2 规上客户 (Scale Customer)

产品宽度 ≥ 阈值（默认 3 个品类）的客户。规上客户是重点维系的优质客户群体。

### 5.3 覆盖率 (Coverage Rate)

某产品被客户/用户购买的比率：
$$覆盖率 = 购买该产品的客户数 ÷ 总客户数 × 100\%$$

### 5.4 潜力产品 (Potential Products)

被标记为重点推广的 **11 个核心产品品类**：
观澜编码产品（非大模型）、出入口停车、前端大模型、网络产品、后端大模型（文搜&多模态）、人员通道、会议平板与视频会议、国密产品、执法记录仪、物联安全、音频产品

### 5.6 Lift 提升度

衡量两个产品之间的购买关联强度：
$$Lift(A→B) = P(B|A) ÷ P(B)$$

- Lift < 1.5：弱关联
- 1.5–2.0：中等关联
- 2.0–3.0：强关联
- 3.0–4.0：极强关联
- ≥ 4.0：超强关联

### 5.7 量价四象限

以"数量同比变化"为 X 轴、"金额同比变化"为 Y 轴，将产品分为：

| 象限 | 位置 | 含义 |
|------|------|------|
| 🟢 成熟核心 | 右上 (量+价+) | 量价齐升，核心优势产品 |
| 🔵 蓝海潜力 | 左上 (量-价+) | 量跌但价增，有提价空间 |
| 🟡 增长见顶 | 右下 (量+价-) | 量增但价跌，需关注 |
| 🔴 弱势品类 | 左下 (量-价-) | 量价齐跌，需重点突破 |

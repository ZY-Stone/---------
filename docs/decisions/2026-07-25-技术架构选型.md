# ADR: 技术架构选型 v2.0

- **日期**: 2026-07-25
- **状态**: 已采纳
- **决策者**: 产品分析一体化平台团队

---

## 背景

V1.x 版本采用 **Vanilla JS + Chart.js (CDN) + FastAPI + SQLite** 架构。经过多轮迭代发现以下核心问题：

1. **数据不可响应式联动** — 上传 Excel 后其他 Tab 的图表/表格不自动更新，需手动调用刷新
2. **代码不可维护** — ~7600 行单文件 `app.js`，全局 `App.xxx` 命名空间，DOM 直接操作
3. **Chart.js 局限** — 复杂图表（四象限散点、双Y轴、热力图）需要大量自定义插件，AI 生成代码一致性差
4. **无类型安全** — 前后端均无类型约束，数据字段硬编码，重构风险高

## 方案对比

| 维度 | 旧架构 (V1.x) | 新架构 (V2.0) |
|------|---------------|---------------|
| 前端框架 | Vanilla JS | React 18 + TypeScript |
| 图表库 | Chart.js (CDN) | ECharts |
| CSS | 手写 CSS | Tailwind CSS |
| 状态管理 | 全局 App 对象 + localStorage | Zustand |
| 后端 | FastAPI (已有) | FastAPI + Pydantic v2 |
| ORM | 无（原生 SQL） | SQLAlchemy 2.0 |
| 迁移 | 无 | Alembic |
| 数据库 | SQLite | SQLite(dev) → PG + ClickHouse(prod) |

## 决策理由

### 1. React 18 + TypeScript
- TypeScript 提供编译期类型检查，消除字段名拼写错误
- React 组件化：每个 Tab/图表是独立组件，职责清晰
- Zustand 比 Redux 轻量，比 Context 性能好，TS 类型推断完美

### 2. ECharts 替代 Chart.js
- **一个 option 对象** 搞定所有图表类型：折线、柱状、散点、漏斗、热力图、双Y轴、雷达、环形
- AI 生成 JSON 配置比生成 Chart.js 命令式代码可靠得多
- 内置 toolbox（下载图片、数据视图）、dataZoom（缩放）、brush（刷选联动）
- 不需要自定义 plugin，四象限背景直接用 markArea

### 3. Tailwind CSS
- 原子化 CSS，不用写样式文件
- 与 React 组件天然契合，删组件时不留孤儿 CSS
- JIT 编译，生产包极小

### 4. FastAPI + Pydantic v2 + SQLAlchemy 2.0
- FastAPI 已有基础，无需重写
- Pydantic v2 性能提升 5-10x，与 SQLAlchemy 2.0 深度集成
- Alembic 管理数据库版本，可追溯可回滚

### 5. SQLite → PostgreSQL + ClickHouse
- SQLite 零配置，开发阶段快速迭代
- 生产环境 PG 做 OLTP（用户、权限、配置），CK 做 OLAP（海量销售明细聚合）

## 影响范围

- **需重建**：前端全部代码（React + TS + ECharts 替代 Vanilla JS + Chart.js）
- **需重构**：后端 models/schemas 层（SQLAlchemy 2.0 + Pydantic v2），services 层保留大部分逻辑
- **保留**：后端 API 路由结构、数据库表设计、产品逻辑（产品宽度/潜力产品计算）
- **移除**：所有硬编码 demo 数据，全部改为从导入数据动态计算

## 数据流新设计

```
Excel 上传
  → 前端 xlsx 解析 JSON
  → POST /api/import
  → 后端写入 sales_width / sales_potential 表
  → 前端 Zustand Store 同步更新
  → Store getter 自动重算（filteredData → kpi → productCoverage → ...）
  → React 组件自动重渲染
  → ECharts option 按需更新（notMerge 模式）
```
